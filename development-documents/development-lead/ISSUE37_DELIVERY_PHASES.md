# Issue 37 delivery phases

User reprioritization: 11 November 2026. The current phase focuses on media/logos,
a simple useful analytics version, and deployment. Other requirements remain
recorded but are postponed; they are not completion gates for this phase.

## Phase 1 — current delivery

- Media/logos: audit and verify existing local SVG assets, accessible labeled
  fallbacks and provenance; pursue genuine replacements for the five remaining
  brands. Do not substitute unrelated icons or fabricated logos. Verify both apps
  serve the correct assets. Keep unresolved source/asset needs explicit.
- Minimal analytics: consented page views, policy opens and CTA clicks; aggregate
  counts by page/policy/button and date. No visitor fingerprinting, unique-user
  claims, search text or registration inference. Validate before sending; late
  consent records the current view once, and revocation stops future sends.
  Complete exact page/revision wiring, isolated bindings, enabled/disabled tests,
  and a small fixed-query report workflow. Plan selection is optional only where
  a real control already exists; richer funnels and dashboards are deferred.
- Deployment: publish and verify the latest wallet and showcase preview sources,
  correct cross-origin allowlists, isolated storage and safe editor setup. Confirm
  HTTP/API/static assets and browser behavior where access is available; report
  external access blockers and exact SHAs/versions on GitHub. No production data
  migration or production release is implied by preview publication.

Acceptance: selected features are implemented and tested, preview source and
runtime evidence agree, reports describe real data or explicitly unconfigured
sources, and remaining phase-1 blockers are named rather than called complete.

## Phase 2 — catalog and editorial rollout (postponed)

Import and editorially review the sourced draft catalog; expand provider/plan/
offer/evidence coverage; complete authenticated D1 approval/publication proof;
verify wallet plan findings with real reviewed content; expand website editing
beyond the implemented intro slots; complete editorial proposal operator rollout.

## Phase 3 — identity, agents and advanced measurement (postponed)

Select/integrate an authoritative account lifecycle and registration ledger;
complete scoped agent credential/revocation and native OAuth/Access routing;
perform actual agent connection verification only when the user lifts its prior
deferral. Add advanced measurement, dashboards and funnels only after the simple
aggregate version is proven.

## Phase 4 — production release (postponed)

Complete the full release audit, protected administrator onboarding, operational
backup/recovery and production approval. Preserve all incomplete requirements in
the completion audit and issue37. Phase completion does not imply full-goal completion.
